# 自动同意连接申请

`auto_accept=true` 仅自动审批收到的连接申请，不代表自动向同群的所有节点申请成员关系。

- 被动发现（mDNS、私有 DHT、成员地址摘要）中的陌生节点不自动信任、不写待审批、不主动交换成员信息。它们只会参与**控制协作**（见下）。
- 已有好友仍可通过发现和冷启动地址簿预热自动重连。
- 用户手动添加节点、连接码或连接种子会发送显式连接申请（info 协议 `connect_request=true`）；后台重连不携带该标记。
- 在自动同意设备上删除成员仍立即生效。被删除成员再次**手动申请**时，自动清除删除记录并恢复信任，无需先被拒绝一次。
- 后台发现、重连和陈旧记录不能越过删除保护。关闭自动同意时仍需要人工批准。

## P2P 连接 ≠ 业务成员

同一网络密钥（同一 `network_key`）下的节点即使**未审批**，也会自动建立 libp2p 连接并做组证明控制协作，用来交换成员摘要 / 地址线索 / PEX / 种子 / 更新分发——这是「同一网络下的主机自动互相认识、网络自我完善」的部分，不需要用户点任何按钮（`pkg/serverless/serverless.go` 的 `addMember` 未信任分支调用 `queueControl`）。

但这**不等于**把这些节点加进来：

- 连接审批（`pending` / `approve`）管的是「**能不能被当成成员访问**」：虚拟 IP 路由、隧道、端口转发、成员表可见性与 ping 全部在审批通过之后才解锁；
- 未审批节点不进成员表、拿不到虚拟地址、不能被访问，界面里也看不到（「附近在线节点」功能已删除，没有展示与申请入口）；
- 组证明只证明「持有群密钥」，绝不等于好友、待审批、中继授权或可发起业务握手的授权。

## 兼容边界

已有好友的普通身份交换和重连不需要申请标记。陌生节点的首次申请、被删除成员的重新申请都必须由申请端发送 `connect_request=true`，否则只拒绝普通握手，不写待审批、不自动同意。旧版没有区分手动申请与后台重连的能力，须升级申请端或由本机用户主动添加，不能为了兼容而把后台探测当成申请。

历史待审批记录没有保存显式申请证据，升级不会擅自批量删除或批准，需用户核对后处理；修复只确保普通握手不再制造新的待审批记录。

## 验证

`go test ./pkg/serverless ./sdk/go/lanet -count=1`

回归覆盖被动发现和出向不触发审批、真实入向自动同意、删除后后台握手不恢复、显式申请直接恢复，以及自动同意关闭与数据库写入失败的保护。
