# 同组协作中转与资源安全

## 权限边界

同密钥且通过本机双向随机挑战证明的节点，可以参与后台中转协作；证明有效期五分钟。第三方地址线索、好友记录、节点协议声明及旧 info 群指纹均不能替代持密钥证明。证明只授权底层中转，不写入业务成员表，不自动审批，也不授予虚拟 IP、端口或业务协议访问权限。

Standalone 节点在 Host 创建前安装拒绝优先的准入，Discovery 未初始化或已关闭时不允许中转。来源和目标必须同时具有本机新鲜同组证明。默认公共群密钥不具有秘密性：公共群的安全依赖配额和业务审批，不能把加入公共群称为可信用户认证。

## 硬资源预算

所有中转服务入口共用有限策略，包括普通、Always 与 Dedicated，不能通过启动方式绕过。

| 项目 | 默认硬预算 |
| --- | --- |
| 单条 circuit | 最长 10 分钟，每方向 64 MiB |
| 预约 | 全局 128、每 peer 1、每 IP 8、每 ASN 32，20 分钟过期 |
| 服务端 circuit 并发 | 每 peer 4；准入额外保守租约全局 64、每来源 IP 8、每端点 4 |
| CONNECT 滑动窗口 | 全局 32/分钟、128/小时；每端点 4/分钟、12/小时；每来源 IP 8/分钟、32/小时 |
| 预约请求 | 全局 128/分钟、每 peer 6/分钟、每来源 IP 24/分钟 |
| 准入状态 | 最多 1024 peer、256 来源地址桶；IPv6 按 /64 合并 |
| 中转 Host | 256 连接、1024 流；每 peer 8 连接、64 流；资源管理内存预算 128 MiB（不是进程 RSS 上限） |

CONNECT 在来源和目标两端同时记账；关闭或失败不返还已扣额度。ACL 没有 circuit 完成通知，因此并发按最长传输加握手余量保守保留约 13 分钟，而非看到关闭就退还。状态满时拒绝新增，不通过淘汰活跃记录让身份轮换刷新额度。未验组请求不扣授权小时额度，便宜的准入回调另有短期并发/频率限制。

**这不是峰值带宽整形，也不是无限流量服务。** 每次 CONNECT 预扣完整双向 128 MiB 的最大传输额度，可限制跨连接累计放大的总量；瞬时网速不由此限制。现有存量 circuit 的额度可能跨统计窗口使用。高吞吐可在十分钟前耗尽字节额度；每端点四次快速重连后可能被保守租约拒绝约十三分钟，每小时上限十二次。直连不消耗中转字节额度。安全限额优先于耗尽后继续高速转发，不应通过无限切换服务器规避它。

## 发现、预约与恢复

- 中转候选最多十个，来自已验证种子、已信任成员，以及有新鲜直接挑战证明且声明 HOP 能力的独立协作缓存。
- 预约每轮最多两个到期/新增候选；成功预约到接近过期才续租，失败按分钟级退避。候选轮转防止末尾饥饿。
- 有效预约仍周期刷新同组证明；证明刷新不新增业务好友。
- 新地址可以有限唤醒发现任务，同一 peer 三十秒最多一次；地址排序变化不会触发。旧代拨号结果不能覆盖新代重试机会，离线失败次数不因换地址清零。
- 隧道按 peer 共用单飞与失败退避，双栈和不同调用方不能各自无限重拨；健康连接复用不消耗新拨号令牌。
- 切换校验实际连接的远端身份与中转路径，不将 `Connect` 返回成功误当成已换服务器。失败隔离不关闭整个 peer，不破坏共享 DHT、控制或其他协议连接。
- echo 往返质量单独计时，不把发现/建连耗时算作链路 RTT；本地取消、错误回显、协议拒绝不能直接证明中转坏。持续劣化需要跨时间多次样本，防止一次抖动就切换。
- 目标 TUN 流只按实际连接身份退役，后续包触发有界重建；这是保守断流恢复，**不承诺既有 TCP 会话无损迁移**。
- 入向 IP 包源地址必须属于已经认证的对端双栈别名，并继续经过防火墙。

## 混合版本与发布门槛

支持现有 control 双向挑战协议的旧节点可继续验组。更早只支持 info 指纹的节点不能使用新版节点提供的中转，不能以好友身份或可观察的群指纹降级绕过。它们的既有直连/旧中转不因此获得新版授权。发布前应确认需要中转的端点均支持挑战协议。

验证须区分：纯预算/权限单测、本机真实 libp2p 多中转测试、内存 TUN 路由互通测试以及现网运行。测试通过不等同于已部署或生产恢复速度实测。不得通过修改服务器、PVE、sysctl 配置来替代应用修复。
