# 0.5.100 连接稳定性修复

## 问题与修复范围

2026-10-25 现场日志包含三类不同的问题，不能只用“网络超时”解释：

1. **普通中继连接周期性断开**：连续三次隧道建立后约120秒关闭，与 libp2p v0.49.0 默认 circuit 连接的两分钟、每方向128KiB限额一致。普通节点中继现在与专用中继一样取消单连接时长和字节限额，但保留默认预约数量、每IP预约数、circuit并发和底层资源管理器约束。不强制普通节点宣告公网可达。
2. **失效成员假上线**：回收后收到陈旧 PEX/DHT 记录会重新创建占位，导致人数变化、空名称以及失效节点互相成为中继。回收成员现在进入有界内存隔离，发现记录只能更新地址并经已有调度器退避重验证，真实审批和同群握手成功才重新发布。隔离上限4096，饱和后未知ID也先验证，不淘汰隔离记录而让旧节点复活。首次发现的正常宽限期保持兼容。
3. **旧隧道挡住新隧道**：退役旧流不能参与仲裁；发起端 single-flight 重拨后，接收端允许同发起方新入向流接管尚未处理EOF的旧入向流。不同发起方继续按PeerID做对称仲裁，不改线协议、不使用两端不一致的本地流编号排序。旧流退役与新流发布在同一锁内完成，延迟旧清理仅按对象身份操作，不删除新流和IPv4/IPv6别名。

中继候选只接纳成功握手且未过期的普通成员，检查实际连接是否非circuit、非Limited，并优先已知支持HOP的节点；种子协议未知时仍可兜底。PEX不再传播从未握手的占位，新增人数日志仅统计真正插入的成员。

## 诊断日志

读取隧道失败时保留真实错误和底层连接/流编号：EOF记录正常关闭，其余错误记录 `read failed`。不再把超时、重置等所有错误都笼统写作 `closed by peer`。编号只供单端日志关联，不能用来跨端比较流代际。

## 验证入口

```powershell
# 普通节点真实中继，大流量双向回显
 go test ./pkg/p2pkit -run TestNodeRelayLargeTransfer -count=1 -v
# 同一底层连接持续超过默认120秒
 $env:LANET_LONG_RELAY_TEST='1'
 go test ./pkg/p2pkit -run TestNodeRelayBeyondDefaultDuration -count=1 -v -timeout=170s
# 失效成员重验证、隧道重拨和基础拨号
 go test ./pkg/serverless ./pkg/tundevice ./pkg/tunnel -count=1 -timeout=180s
```

长测使用真实 libp2p 普通节点中继，确认预约返回无限时/无限单连接字节额度，显式验证实际走circuit、传输内容一致以及同一连接编号保持不变。Linux CI也执行跨两分钟长测。

## 本次本地验证结果

- 真实普通中继持续传输125秒通过，同一底层连接保持；初始双向每方向传输1,179,648字节，随后每秒继续回显。
- Windows核心模块测试通过；干净源码副本全仓库 `go test ./...`、`go vet ./...` 通过。验证副本排除无关临时调试源码和Windows管理员资源清单，不改动工作目录原文件。
- 真实双端同时建流、仲裁、关闭传播和并发重建恢复专项重复20次通过；同发起方跨代恢复重复30次通过。
- Windows客户端0.5.100构建通过。
- 本机CGO禁用且Windows未配置C编译器，尚未在本机完成race；隔离Linux构建镜像下载无进度，停止后交给既有Linux CI执行，不能将上述普通测试当成race结果。

## 部署与边界

- 本地测试不等于现场多机TUN验证。上线后需收集两端版本、真实中继节点、关闭错误及连续ICMP/TCP传输结果。
- 仅更新发起端不能更改旧中继的服务端限额；实际承担中继的普通节点也必须更新到0.5.100或后续版本。
- 外部不可达的10.70网段地址不会因本修复变得可达。修复目标是隔离失效信息和无效候选，不是绕过路由/防火墙。
- 不新增持久化。程序重启后可再次首次发现历史成员，但运行期间回收后不会仅凭陈旧摘要反复假上线。
- 不引入共享代际序号，跨底层连接的入向handler任意代际重排仍不承诺完全收敛；保留真实错误日志以识别是否需要后续协议级升级。
- 取消单连接额度不意味着无限并发或内存；仍保留libp2p的其他资源上限，不等于带宽限速。
