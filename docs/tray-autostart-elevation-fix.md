# 托盘图标登录后不出现：任务定义缺最高权限声明（0.5.101）

## 现象

Windows 重启（或重新登录）后任务栏没有 Lanet 托盘图标。节点本体一切正常：服务「Lanet」为 Running、虚拟 IP 不变、其他成员在线，只是没有那个图标，也没有任何报错弹窗。

## 根因

三件事叠加，缺一不可：

1. `lanet.exe` 内嵌 **requireAdministrator** 清单（TUN 虚拟网卡必需，实测二进制中包含 `requireAdministrator`、不含 `asInvoker`）。
2. 托盘图标不可能画在服务里（服务在 Session 0），所以由计划任务「Lanet Tray」在用户会话拉起；任务定义必须声明 `<RunLevel>HighestAvailable</RunLevel>`，让任务计划程序**代为提权**，用户全程看不到 UAC。
3. 若任务是由**未提升的进程**注册的（旧版在用户会话里跑控制台开「开机自启」，或手工 `schtasks`），Windows 会**静默丢弃**这条声明，落成一个「最低权限」任务。

于是登录触发时，任务计划程序启动一个要求管理员的 exe 却没有提权 → 直接失败 `0x800702E4`（`ERROR_ELEVATION_REQUIRED`），图标永远不出现，且没有用户可见的错误。

真机证据（2026-10-26 本机 `D:\lanet-node`）：

| 检查项 | 实测值 |
|---|---|
| 任务定义 | 有 `LogonType=InteractiveToken`，**没有** `RunLevel` 元素 |
| 任务描述 | 仍是旧版文案，说明是旧版本注册后未被修正 |
| 最近运行时间 | 2026-10-25 23:08:25（服务更新完拉起那次） |
| 最近运行结果 | `2147943140` = `0x800702E4` 需要提升 |
| exe 清单 | `requireAdministrator` |

原实现的服务兜底只判断「任务**存在**」就直接拉起，从不校验定义内容，所以这类过期任务会一直留着，每次登录都失败。

## 修复

- 新增 `app/agent/cmd/pvn-node/tray_task_check_windows.go`：读取 `schtasks /Query /TN "Lanet Tray" /XML` 后判定定义是否过期，覆盖四类漂移——最高权限声明缺失、程序路径变化、启动参数（`-tray` 与配置路径）丢失、触发用户变化。判定是纯函数，输入只有任务定义文本，便于用真实任务 XML 做回归。
- 编码归一化：`schtasks` 的 stdout 实测是本地代码页/UTF-8 字节，但声明里写 UTF-16；同时任务定义文件本身是 UTF-16LE。三种真实形态（UTF-16LE 带/不带 BOM、UTF-16BE、含 GBK 非法字节）都先归一化成合法 UTF-8，解析才不会因为中文描述而失败。
- `ensureTrayAutostartFromService`（服务启动兜底）：任务已注册时**先校验定义**，过期就按当前登录用户 `/F` 重建（服务是 LocalSystem，能写出最高权限声明）再立即拉起；尚未登录、拿不到交互用户时不比较用户字段，避免误重建别人的任务。注册动作收敛到 `adoptTrayTaskForUser` 一处实现，补注册与过期重建共用。

## 验证

```powershell
# 托盘任务判定（含真机过期定义夹具、编码、自洽性）
go test ./app/agent/cmd/pvn-node -run Tray -count=1 -v
```

`app/agent/cmd/pvn-node` 内含 Windows 管理员资源清单，测试副本会报 requires elevation；按既有做法在排除 `*.syso` 的干净副本里运行。

本地结果：

- `-run Tray` 全部通过，包括：真机过期定义（缺 `RunLevel`）被判为过期且原因点明 `0x800702E4`；健康定义不误判；换目录/丢 `-tray`/丢配置路径/换用户四种漂移；UTF-16LE 带 BOM、UTF-16LE 无 BOM、UTF-8、含 GBK 字节四种编码；按当前版本生成的定义自洽（不会被自己判成过期）。
- 用真机 `schtasks` 原始输出字节额外跑了一次字节级校验（临时用例，未提交）：解析出 `Command=D:\lanet-node\lanet.exe`、`RunLevel=""`、`TriggerUser=ANYANG-PC\ay`，判定为过期。
- 干净副本 `go test ./...` 全仓库通过、`go vet ./app/agent/cmd/pvn-node` 无输出。

## 真机验证结果（2026-10-26，本机 `anyang-job-pc`）

热更新到 0.5.101 后，服务重启时经该兜底逻辑自愈，实测：

| 检查项 | 更新前 | 更新后 |
|---|---|---|
| 任务 `RunLevel` | 缺失（最低权限） | `<RunLevel>HighestAvailable</RunLevel>` |
| 任务描述 | 旧版文案 | 新版文案（含「节点本体由服务运行」说明） |
| 节点日志 | 无相关记录 | `[tray] 托盘任务定义过期（任务未声明以最高权限运行……0x800702E4）：已按当前版本注册托盘任务（登录用户 ANYANG-PC\ay）` → `[tray] 已请求任务计划程序立即启动托盘` |
| 任务运行结果 | `0x800702E4` 需要提升 | `0x00041301` 正在运行 |
| 托盘进程 | 不存在 | PID 32184，**SessionId=1**（用户会话），日志 `托盘伴侣启动` + `节点控制台 = http://127.0.0.1:8900` |

服务本体（Session 0）继续由 Windows 服务运行，托盘只负责图标，两者互不抢占 TUN/端口。

## 边界

- 只在**服务模式**生效；便携模式（非服务运行）本来就在用户会话里直接启动托盘，不需要计划任务。
- 自愈发生在**服务启动时**：已经坏掉的任务需要服务重启（或下次开机）才会被重建，不会在运行期间凭空刷新。
- 修复依赖交互式登录会话：快速用户切换/多用户并行时，按最近探测到的交互用户重建任务。
- 任务定义被外部安全策略禁止创建（而不是被降级）时，仍会打印失败日志并提示从控制台重开一次「开机自启」，不会静默失败。
- 不做持久化、不改线协议、不改变托盘功能本身；只是让已存在的错误任务能被自愈。
